## Couverture (A5.5)

- Outil : `pytest-cov` 7.1.0 et `coverage` **7.17.0**, ajoutés au groupe `dev`. `coverage` est épinglé
  sur une version de plus de deux semaines (7.17.3 avait 4 jours).
- Configuration dans `backend/pyproject.toml` :
  - le processus d'inférence (`spawn`) et les CLI lancées par les tests sont mesurés
    (`patch = ["subprocess"]`). Sans cela, `worker/inference.py` plafonnait à 70 % : tout le code de
    l'enfant passait pour non testé ;
  - exclus : l'adaptateur Idol (exclu par le critère lui-même ; couvert par les tests `gpu`) et les quatre sondes de
    faisabilité de P0 (`probes/cuda.py`, `gpu_load.py`, `idol.py`, `presets.py`). Ces sondes ne sont
    jamais importées par l'application, ne tournent que sur le GPU (profil Compose `probe`), et
    pèsent 397 lignes. `probes/ply.py`, testé sans GPU, reste compté.

| Périmètre | Mesuré le 2026-11-16 | Seuil |
|---|---|---|
| Backend hors Idol et sondes GPU | **92,9 %** (3 289 lignes) | 85 % |
| Domaine et file (`domain/`, `queue/`) | **98,9 %** (265 lignes) | 95 % |

Pour comparaison, sans mesurer les sous-processus et sans exclusion : 80 %.

- Les seuils mordent : `--fail-under=94` fait sortir `coverage report` en code 2.
- `.coverage*` est ignoré par git : les fichiers des sous-processus portent le nom de l'hôte.

## Correction annexe : test instable du visualiseur

Le run de P5.1 (43843916139) a échoué sur `ResultViewer.test.tsx`, « affiche la progression réelle
du téléchargement », sans rapport avec P5.1. La barre de progression peut entrer dans le DOM avant
que l'effet qui lance le téléchargement ait tourné : la génération arrive par une promesse, hors
`act`, et React diffère l'effet. La progression envoyée par le test partait alors dans le vide. Le
test attend maintenant l'appel de téléchargement du PLY. La course n'a pas été reproduite en local
(une API ralentie ne la déclenche pas) : le correctif vise le mécanisme, sans preuve de reproduction.
