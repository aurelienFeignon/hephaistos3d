# P3.3 — Import et aperçu de l'image

État : implémenté et vérifié le 2026-11-09. Le gate P3 n'est pas validé. La soumission arrive avec
le formulaire (P3.4) : le bouton Générer reste désactivé.

## Implémentation

- `frontend/src/lib/image/inspect.ts` contrôle dans l'ordre le poids et le format (schéma zod), le
  décodage, puis le nombre de pixels. Le format est lu dans les premiers octets, car le navigateur
  déduit `File.type` de l'extension : un fichier renommé `.png` est refusé.
- `frontend/src/components/studio/ImagePicker.tsx` : sélection au clic, au clavier ou par dépôt,
  aperçu, dimensions, poids, transparence, retrait, messages de refus. L'URL de chaque aperçu est
  libérée au remplacement, au retrait et au démontage ; une lecture dépassée par un choix plus
  récent est ignorée.

## Écarts assumés avec le backend

- `UPLOAD_MAX_BYTES` et `UPLOAD_MAX_PIXELS` sont réglables côté serveur mais pas exposés par l'API.
  Le client reprend leurs valeurs par défaut, et un test échoue s'ils s'en écartent. Si un
  exploitant les modifie, le client appliquera encore les valeurs par défaut.
- La transparence est analysée sur une version réduite à 1024 px de côté au plus : un pixel
  transparent isolé peut échapper à l'indication, qui reste informative. Le backend reste la référence.
- Une image tronquée que le navigateur sait afficher sera refusée par l'API seulement.

## Vérifications

- 24 tests Vitest ajoutés (59 tests frontend au total), observés en échec avant implémentation.
  Six mutations détectées puis restaurées : signature WebP, plafond de pixels, libération après
  refus, lecture périmée, libération au remplacement et reprise du même fichier.
- Parité navigateur et backend sur 11 vrais fichiers générés avec Pillow, dans Chromium avec le
  build de production. Dimensions et transparence affichées égales à celles de `normalize_image`,
  dont un JPEG en orientation EXIF 6 (400 × 200 affiché 200 × 400), un PNG à alpha entièrement opaque
  et un WebP transparent. Fichier texte renommé, GIF renommé, PNG corrompu, 48 Mpx et plus de 20 Mio
  refusés avec un message explicite. Ce contrôle a été joué à la main : il n'est pas dans la CI.
- ESLint, `next typegen`, `tsc --noEmit` strict, `api:check` et build de production verts.
