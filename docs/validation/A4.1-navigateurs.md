# A4.1 — PLY de 262 144 et 1 048 576 gaussiennes dans Chrome et Firefox

État : vérifié le 2026-11-11 sur le poste cible, GPU réel. Le gate P4 n'est pas validé.

## Banc

- Pile Compose complète et isolée, construite depuis `main` (migration, API, janitor, frontend, worker du
  profil `gpu`) : projet, données, cache et images dédiés, sans redémarrage automatique. Poids d'Idol en
  lecture seule ; `GPU_MIN_FREE_VRAM_MB=8192`, déchargement du modèle après 120 s d'inactivité.
- Accès comme pour A3.2 : frontend sur `127.0.0.1:3030`, atteint depuis le poste de l'utilisateur par
  **redirection de port SSH**, sans ouverture sur le LAN.

## Défaut trouvé et corrigé

Deux générations supplémentaires, faites par l'utilisateur sur une illustration sans perspective (un
appareil photo), s'affichaient en **écran noir** dans les deux tailles. Les PLY étaient sains ; Idol avait
prédit une caméra quasi orthographique : **1000 unités de distance, 0,08° de champ**, contre 1,7 à 5,7 unités
et 19 à 62° ailleurs. Le visualiseur ne dessine rien au-delà de 100 unités : l'objet était coupé (0 pixel
d'objet, reproduit dans la page de preuve).

Correction (`lib/viewer/idolCamera.ts`, `initialView`) : sous 10° de champ, la vue initiale garde la même
direction et la même largeur visible à l'origine, avec un champ de 30° et la distance correspondante
(environ 2,8 unités ici). Les caméras ordinaires ne changent pas ; le panneau « Informations » affiche
toujours la prédiction brute. Rendu du cas réel : l'objet s'affiche, même point de vue que l'image
d'entrée. Test sur les valeurs mesurées (une mutation du seuil le fait rougir), 254 tests Vitest et
11 parcours Playwright verts ; vérifié par l'utilisateur sur le banc reconstruit.
