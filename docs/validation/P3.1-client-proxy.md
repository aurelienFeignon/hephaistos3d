# P3.1 — Types, client HTTP et première partie du proxy P3.9

État : implémenté et vérifié le 2026-11-05. L'utilisateur a autorisé le passage à P3 après
les corrections de sécurité P2. Le gate P3 n'est pas validé ; les écrans Studio restent à construire.

## Implémentation

- `backend/scripts/export_openapi.py` exporte le contrat sans démarrer de service ni ouvrir la
  base de données. Un secret factice sert uniquement à construire la factory hors ligne.
- `frontend/scripts/generate-api.mjs` génère `src/lib/api/schema.d.ts` avec openapi-typescript.
  Il ne transmet pas les réglages/secrets locaux au processus d'export.
  `npm run api:check` compare le résultat en mémoire, sans réécrire le fichier ; la CI vérifie
  cette absence de dérive avant les tests frontend.
- `src/lib/api/client.ts` expose les ressources typées et leurs actions : filtres, pagination,
  multipart, état système, tentatives/journaux. Les erreurs problem+json conservent statut, code
  et détails de validation. Les erreurs non JSON restent génériques ; les AbortSignal sont transmis.
- Le client navigateur appelle uniquement `/api/v1`, sans jeton. Le module `server-only`
  `src/server/api-proxy.ts`, utilisé par le Route Handler Next, ajoute le secret côté serveur.
- Le proxy vérifie le Host exact, refuse les requêtes cross-site et exige une Origin autorisée
  et correspondant au Host pour les mutations. Les en-têtes forwarded du navigateur ne sont pas
  utilisés pour décider de l'autorisation. Les cookies et Authorization du navigateur sont retirés.
- Les ressources autorisées sont explicites ; les chemins arbitraires, les docs et les échappements
  sont refusés. L'URL amont est une origine HTTP(S) configurée côté serveur, jamais un paramètre client.
  Les redirections amont sont refusées afin de ne pas transmettre le secret à une autre destination.
- Uploads et téléchargements sont transmis en flux, sans conversion globale en mémoire. Les corps
  sont bornés, avec ou sans Content-Length ; les délais et annulations sont propagés. Les en-têtes
  Range, ETag, Content-Range, Location locale et X-Next-Attempt utiles sont conservés. Pas de cache.

## Configuration locale

Le secret `API_ACCESS_TOKEN` reste dans le `.env` ignoré à la racine. Il n'est pas dupliqué dans
un fichier frontend. `npm run dev` et `npm start` utilisent Node 24 pour charger ce fichier puis
lancer Next sur **127.0.0.1:3030**. Le build n'a besoin d'aucun secret ni backend en fonctionnement.
Aucune variable de secret n'utilise `NEXT_PUBLIC_*`.

`HEPHAISTOS_API_URL` vaut `http://127.0.0.1:8000` en développement ; le futur service Compose
frontend utilisera `http://api:8000`. `FRONTEND_ALLOWED_ORIGINS` contient les origines exactes du
frontend, ports compris. Le backend doit autoriser ces mêmes origines dans `API_ALLOWED_ORIGINS`.
Le proxy exige Origin pour les mutations ; un client HTTP manuel doit aussi l'envoyer.

La configuration Compose actuelle reste celle du backend P2, sans port publié. L'ajout du service
frontend et de son image standalone reste à faire en P3.9. Aucun déploiement permanent n'a été lancé.
Un appel direct au backend exige toujours son jeton. Le contrôle d'accès utilisateur au frontend
avant ouverture LAN demeure distinct du secret interservices, conformément à la décision utilisateur.

## Vérifications

- **30 tests Vitest** : client typé, erreurs et annulations ; Host/Origin, absence d'Origin,
  chemins, jeton serveur, cookies retirés, redirections, flux bornés, délais et fichiers partiels.
- Cinq mutations détectées puis restaurées : suppression du contrôle Host sur les lectures,
  retrait du contrôle Origin, retrait de la borne en flux, mauvais jeton injecté et dérive du fichier généré.
- ESLint, types Next/TypeScript strict et build Next de production réussis.
- Chaîne HTTP réelle avec **Next en production et FastAPI**, base et images temporaires :
  modèles, rejets Host/Origin, PUT admis, upload multipart → QUEUED, source PNG, file paginée et
  suppression 204. Docs proxy et trois routes P0 renvoient 404. Jeton absent des assets navigateur.
  Les deux processus temporaires ont été arrêtés ; aucun GPU ni donnée réelle utilisés.
- Les 532 tests backend de la correction P2 restent la dernière suite complète validée ; ce lot
  ne modifie pas les comportements du backend. Le nouvel exporteur est contrôlé par Ruff.
