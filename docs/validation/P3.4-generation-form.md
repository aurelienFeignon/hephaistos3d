# P3.4 — Modèle, préréglages et formulaire générique

État : implémenté et vérifié le 2026-11-09. Le gate P3 n'est pas validé.

## Implémentation

- `frontend/src/lib/forms/engine.ts` lit le sous-ensemble JSON Schema, applique les préréglages et
  valide les saisies. Il ne contient aucun nom de paramètre propre à un modèle.
- `frontend/src/components/studio/ParamsForm.tsx` rend les widgets `radio`, `select`, `slider`,
  `number` et `toggle` ; les champs `advanced` vont dans la section Avancé.
- `frontend/src/components/studio/GenerationPanel.tsx` charge les modèles, leur schéma et leurs
  préréglages, puis soumet `POST /generations`. Seules les valeurs qui diffèrent du préréglage sont
  envoyées ; la graine est un champ de l'API, indépendant du modèle.
- Backend : `x-ui.labels`, facultatif et contrôlé par `schema_violations`, nomme les valeurs d'un
  `enum` (Rendu / Photo pour Idol). Sans lui, le frontend aurait dû coder ces libellés en dur.

## Choix et limites

- F3 demande un modèle indisponible « grisé ». `available` signifie seulement qu'aucun worker
  n'envoie de signal récent, or l'API accepte alors la soumission, qui attend avec le motif
  `NO_WORKER` (A2.15). Le modèle reste donc sélectionnable, marqué indisponible avec sa raison.
  Cette raison vient de l'API et reste en anglais.
- La tolérance de `multipleOf` reprend le comportement mesuré sur pydantic-core 2.50 : absolue,
  1e-9. Une montée de version de Pydantic qui la changerait n'est pas détectée automatiquement.
- `x-ui.group` n'a pas de rendu propre : aucun titre de groupe n'est publié, et `order` garde déjà
  les champs d'un groupe côte à côte.
- Après une soumission réussie, le suivi n'existe pas encore : il arrive avec la file (P3.5).

## Vérifications

- A3.3 : formulaire rendu depuis un schéma factice sans rapport avec un modèle réel, puis depuis
  les schémas réels d'Idol et de l'adaptateur factice.
- A3.4 : dans Chromium, une valeur hors bornes est refusée sans aucune requête POST ; la même
  requête forcée à travers le proxy rend 422 `PARAMS_INVALID`.
- Parité du validateur et de Pydantic sur 1792 cas du schéma Idol réel : 0 écart. Un premier passage
  a révélé une tolérance mal supposée, corrigée et couverte par des tests.
- Chaîne réelle Chromium → proxy Next de production → FastAPI, sur base temporaire et jeton jetable,
  sans GPU : générations `QUEUED`, préréglage, surcharges, type d'image et graine relus par l'API.
  Ce contrôle a été joué à la main : il n'est pas dans la CI.
- 48 tests Vitest ajoutés (107 au total) et 6 cas backend (538 tests sans GPU), Ruff, format, mypy,
  ESLint, `tsc`, `api:check` et build verts. Six mutations sur sept détectées par les tests ; la
  septième, le retrait de la garde de soumission, est refusée par `tsc`.
