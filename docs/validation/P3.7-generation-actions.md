# P3.7 — Actions sur les générations

État : implémenté et vérifié le 2026-11-09. Le gate P3 n'est pas validé.

## Implémentation

- `frontend/src/components/studio/GenerationActions.tsx` : annuler, relancer, protéger et supprimer
  depuis le détail, selon le statut. La suppression demande une confirmation, dont le choix par défaut
  est de conserver la génération.
- `frontend/src/components/studio/QueueBar.tsx` : annulation directe depuis la file.
- `frontend/src/components/studio/Studio.tsx` : après une action, la file, la bibliothèque et le détail
  sont relus aussitôt, sans attendre le prochain cycle.

## Choix et limites

- L'API ne publie pas qu'une annulation coopérative est en attente. L'interface le retient localement :
  « Annulation demandée » disparaît donc si la page est rechargée, alors que la demande reste active.
- La relance n'est pas proposée pour `INGEST_FAILED`, que l'API refuse : il faut importer l'image à nouveau.
- La suppression reste possible sur une génération protégée, comme le prévoit l'API : seule la
  rétention automatique l'épargne. La confirmation le rappelle.
- Après un refus, un message explique la cause et l'état est relu.

## Vérifications

- Chaîne réelle Chromium → proxy Next de production → FastAPI → vrai superviseur avec l'adaptateur
  factice, sur base temporaire, sans CUDA ni inférence GPU : annulation depuis la file et depuis le
  détail, annulation coopérative d'une génération `RUNNING`, relance, protection, 409 réel expliqué,
  suppression refusée à l'affichage en `RUNNING`, « Conserver » sans effet, suppression confirmée avec
  réponse 404 et disparition effective des dossiers sources, résultats et journaux.
- Ce contrôle a été joué à la main ; il n'est pas dans la CI et reste à automatiser avec A3.1.
- 30 tests Vitest ajoutés (196 au total), observés en échec avant implémentation, ESLint, `tsc` et build
  verts. Neuf mutations détectées puis restaurées.
