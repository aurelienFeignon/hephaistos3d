# P3.5 — File et progression

État : implémenté et vérifié le 2026-11-09. Le gate P3 n'est pas validé.

## Implémentation

- `frontend/src/lib/api/usePolling.ts` : interrogation sans chevauchement. Le délai suivant part de la
  fin de la réponse. Quand l'onglet est masqué, le minuteur s'arrête et la requête en cours est
  annulée ; au retour, une requête part immédiatement.
- `frontend/src/components/studio/QueueBar.tsx` : position, motif d'attente, étape, pas `i/N`, durée.
  La barre n'apparaît que si l'API publie un pas et un total : aucune progression n'est estimée.
- `frontend/src/components/studio/Studio.tsx` relie le panneau à la file : une création déclenche une
  lecture immédiate, sans attendre le prochain cycle.

## Choix et limites

- Seul `GET /queue` est interrogé : il porte déjà les générations `QUEUED` et `RUNNING` avec leur
  position, leur motif et leur progression.
- Rythme : 2 s tant que la file contient une génération, 15 s sinon, et 15 s après un échec. Un échec
  conserve la dernière file connue et affiche un message.
- La durée vient de l'API et se met à jour à chaque lecture, sans compteur local.
- Seules les 50 premières entrées sont affichées.
- Une génération terminée quitte la file : son résultat apparaîtra dans la bibliothèque (P3.6).
  L'annulation depuis la file arrive avec les actions (P3.7).

## Vérifications

- Chaîne réelle Chromium → proxy Next de production → FastAPI → vrai superviseur avec l'adaptateur
  factice, sur base temporaire, sans CUDA ni inférence GPU :
  - F6 : génération visible dans la file en moins de 2 s (98 ms mesurées) ;
  - F7 : position et motif affichés, distribution suspendue puis reprise ;
  - F8 : pas réel croissant, barre égale au pas publié, durée affichée, aucun pourcentage ;
  - rythme mesuré de 2,0 s en activité, aucune interrogation rapide au repos ;
  - A3.6 : aucune requête pendant 6,5 s onglet masqué, reprise immédiate au retour.
- L'onglet masqué est simulé par `document.hidden` et l'événement `visibilitychange`.
- Ces contrôles ont été joués à la main ; ils ne sont pas dans la CI et restent à automatiser avec A3.1.
- 27 tests Vitest ajoutés (134 au total), observés en échec avant implémentation, ESLint, `tsc` et build
  verts. Neuf mutations détectées puis restaurées.
