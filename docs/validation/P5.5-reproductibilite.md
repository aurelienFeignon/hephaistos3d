# P5.5 — Reproductibilité des images (A5.4)

État : vérifié le 2026-11-17 sur `0e6fec6`. Le gate P5 n'est pas validé.

## Méthode

Trois constructions des images `api`, `worker` et `frontend` du même commit :

| Construction | Cache |
|---|---|
| `maj` | `docker compose --profile gpu build` ordinaire, après une construction de `5f60dfc` |
| `nocache` | `docker compose --profile gpu build --no-cache` dans un clone neuf |
| `vierge` | même commande, avec un **builder BuildKit créé pour l'occasion** (`docker buildx create --driver docker-container`), puis supprimé |

`--no-cache` écarte le cache des couches, **pas** les montages `--mount=type=cache` du Dockerfile :
la construction `nocache` a donc pu relire le cache de uv. La construction `vierge` part d'un builder
sans aucun cache : elle a retéléchargé toutes les dépendances (6 min 42 s). C'est elle qui tient lieu
de « machine propre ».

Listes comparées : toutes les distributions Python du venv (`importlib.metadata`, l'équivalent de
`uv pip freeze` : uv n'est pas dans l'image d'exécution) et tous les paquets de `node_modules` de
l'image `frontend` (sortie autonome de Next, l'équivalent de `npm ls` sur ce qui est livré).

## Résultat

| Image | Paquets | `maj` = `nocache` | `maj` = `vierge` |
|---|---|---|---|
| `api` | 33 | ✅ identiques | ✅ identiques |
| `worker` | 89 (dont `torch 2.14.1+cu132`, `idol 0.1.0` au commit `4702a7f`) | ✅ | ✅ |
| `frontend` | 14 (dont `next 16.4.5`, `react 19.3.1`) | ✅ | ✅ |

Les versions viennent de `backend/uv.lock` (`uv sync --frozen`) et de `frontend/package-lock.json`
(`npm ci`). Les images de base sont épinglées par empreinte.

## Limites

- La comparaison porte sur les **versions**, pas sur les octets : les identifiants d'image diffèrent
  (horodatages des couches), ce qui est attendu.
- La liste npm couvre les paquets livrés dans l'image, pas l'arbre de construction complet.
- Même machine et même démon Docker : un autre hôte n'a pas été essayé.
